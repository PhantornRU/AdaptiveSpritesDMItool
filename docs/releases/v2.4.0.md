# Adaptive Sprites DMI Tool v2.4.0

V2.4.0 expands the verified V2.3 editor and DMI pipeline with native PNG workflows and a format-independent document layer.

## Documents and import

- `SpriteDocument` keeps ordered states, 1/4/8 directions, animation metadata, source crops, and explicit transforms without retaining every decoded frame in memory.
- Files are identified from PNG signatures and DMI metadata instead of extension alone.
- The Documents workspace opens native DMI or sidecar projects and imports a static PNG, ordered PNG sequence, or configured sprite sheet.
- Sprite-sheet import validates cell size, margins, spacing, row/column reading order, direction order, frame count, and inclusive source bounds before it changes the active document.
- New imports can create a document, add non-conflicting states, or add the selected frame as an auxiliary editor layer.

## Persistence and export

- `<name>.adaptive-dmi.json` sidecars use schema v1 and store relative plus fallback source paths, content format, dimensions, encoded size, SHA-256, crops, transforms, state order, and animation metadata.
- Missing or changed sources are never accepted silently; load supports explicit relink or fingerprint acceptance.
- DMI document export writes beside the destination, reopens the result, and verifies ordered metadata and normalized RGBA hashes before atomic commit.
- DMI hotspot metadata is normalized around the DMISharp 2.1.0 serializer limitation and included in reopen verification.
- PNG sheet and sequence outputs use sibling staging and a tool ownership manifest. Unmanaged directories are never replaced.

## Workspace and batch

- Workspace schema v8 stores the last sidecar, generic DMI/PNG auxiliary layers, selected DMI/PNG batch formats, and the raster direction/layout profile.
- Workspace v7 migrates automatically with DMI and PNG selected and a 4-direction PNG sheet profile.
- Batch accepts DMI and ordinary PNG inputs, applies the current mapping without reinterpreting mirror settings, and writes DMI and PNG outputs independently.
- Same-stem inputs that resolve to one output path are rejected explicitly instead of being processed in file-system order.
- PNG profiles support 1, 4, or 8 directions. A 4-direction config supports 1/4 profiles; an 8-direction profile requires an 8-direction config.
- One output failure does not block the other format for the same input.

## Safety limits

- 128 MiB encoded source
- 16,384 pixels per dimension
- 67,108,864 decoded pixels
- 4,096 frames, cells, or source frames
- 1,024 states

Probe and checked-arithmetic validation run before bulk decode. Cancellation or validation failure leaves the active document, sidecar, and destination unchanged.

## Compatibility

- Mapping JSON remains schema v2 and still reads v1.
- CSV remains import-only.
- The public `IDmiWriter` contract is unchanged.
- Workspace v6/v7 and the existing V2.3 editor settings remain readable.
- V2.4 intentionally supports native DMI and PNG only; other raster codecs and Aseprite/PSD/KRA/XCF/SVG/ZIP workflows remain future scope.
