# Adaptive Sprites DMI Tool v2.3.0

V2.3.0 focuses on predictable editor mutations and safe DMI output.

## Editor

- Paint, Erase, Restore, Fill, Move, and Select/Move are calculated first and committed atomically.
- Fast pixel strokes use supercover interpolation and create one Undo entry per gesture.
- Erase writes transparent RGBA; Restore removes the mapping and exposes the original pixel.
- Mirroring uses `x' = width - 1 - x + 2 * offsetPixels` without clamping.
- Out-of-bounds projected targets are skipped and counted; the primary edit is retained.
- The mirror axis can be shifted by whole pixels and shown as an independent canvas guide.

## Data compatibility

- Config JSON schema is v2 and adds `editorSettings.mirrorAxisOffsetPixels`.
- Workspace schema is v7 and stores the last axis offset, guide visibility, and direction-mirroring toggle.
- Config v1 and Workspace v6 remain readable and migrate with a centered axis.
- CSV remains import-only and receives a centered axis.

## DMI safety

- State order is preserved.
- Output is written to a unique temporary file beside the destination.
- The temporary DMI is closed, reopened, and checked for ordered metadata and SHA-256 of normalized RGBA frames.
- Existing output uses `File.Replace`; new output uses a same-volume `File.Move`.
- In-place save is supported. Verification, cancellation, or replacement failure leaves the original file unchanged and removes the temporary file.
- Integration coverage uses asymmetric 3x3/4x4, multi-state and multi-frame fixtures and compares mapping, preview, and reopened-DMI RGBA hashes.

## Platform

- .NET 10 LTS
- CommunityToolkit.Mvvm 8.4.2
- Microsoft.Extensions Hosting/DI/Logging 10.0.10
- ImageSharp 3.1.12
- WPF-UI 4.3.0
- DMISharp 2.1.0

NuGet restore uses committed lock files in CI. CI builds Debug and Release, runs Release tests, audits vulnerable dependencies, and packages the self-contained `win-x64` ZIP.

## Compatibility boundaries

- The public `IDmiWriter` contract and the DMI/CSV formats are unchanged.
- `Assets/Import`, `Assets/Export`, `Assets/Storage`, and `Assets/Saves` retain their existing path contracts.
- Batch processing consumes the mappings already stored in the config and does not reinterpret editor mirror settings.
- JSON v1 and Workspace v6 remain accepted inputs; only newly saved data is upgraded to JSON v2 and Workspace v7.
